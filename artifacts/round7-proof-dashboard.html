Runvouch protocol gap — addressed

The 2026-09-01 comment on the RFC asked whether the backlog coalesces per job and pointed out the missing lastDeferralReason field. Both addressed.

Per-job coalesce — already correct

byJobId Map in maintenance-deferred.ts: repeat defers within a phase only refresh lastDeferredAtMs; no new FIFO entry is created. The replay is one run per job with nextRunAtMs = max(lastDeferredAtMs, now - 1).

lastDeferralReason — added

Closed enum: maintenance_window | manual_run_blocked | agent_role_mismatch | scheduler_backoff. Set at defer time (so the field is visible during the hold) and re-stamped at phase exit (so the field survives across phase transitions).

src/cron/service/timer-runnable.ts + src/cron/maintenance-policy.ts + packages/gateway-protocol/src/schema/cron.ts

missedScheduleTicksEstimate — added

For {kind: "every"} schedules the count is exact: max(1, floor(holdMs / everyMs)). For cron-syntax schedules it is conservative (one tick per minute max) and marked approximate via missedScheduleTicksEstimateIsApproximate.

src/cron/maintenance-policy.ts + src/cron/types.ts + packages/gateway-protocol/src/schema/cron.ts

Doc drift — fixed

Schema comment in packages/gateway-protocol/src/schema/cron.ts and the JSDoc on CronJobState in src/cron/types.ts both now describe the actual cumulative semantics instead of the stale "cleared at phase exit" wording.
