Round 7 — new scenarios

scenario_14_iana_timezone_validation

Schema-level IANA check rejects unknown zones at config-load time. A typo no longer silently falls back to the operator's local zone — the maintenance window is the one the operator actually wrote.

"iptla_accepted":      true    // America/Los_Angeles → real IANA
"bad_zone_rejected":   false   // Not/A/Real/Zone → unknown IANA timezone
"user_alias_accepted":  true    // 'user' → resolver falls back to userTimezone
"local_alias_accepted": true    // 'local' → resolver uses Intl resolved zone
"end_24_00_accepted":   true    // end='24:00' → end-of-day sentinel accepted
"end_24_30_rejected":   false   // only '24:00' sentinel, no '24:30'
"start_after_end_rejected": false   // start ≥ end → superRefine rejects
